# 每日活跃统计

后台「概览」的「每日活跃用户 · 按平台」表随页面的 7 / 30 / 90 天范围切换，
按日期倒序展示合计与 Windows、macOS、Linux、Android、iOS 明细。

统计沿用现有口径：以服务端接收 `activity` 的 UTC 日期为准，每个平台每天按设备标识去重。
重复请求、重新启动或同日重装不会重复计算日活。这里统计的是活跃设备，
同一人使用多台设备会分别计数，并非按登录账号去重。
没有活跃记录的日期和平台显示 0；安卓历史上未上报的活跃无法补算。

## 移动端上报

- 会话恢复完成后启动统计，未登录也可上报；登录后使用所选服务器。
- 启动、回到前台，以及前台每分钟检查当天是否已成功上报。
- 每个服务器每天成功上报一次，失败不记为成功，后续前台检查会重试。
- 请求有 10 秒超时，串行读写上报状态；后台停止检查，卸载组件时清理计时器和监听。
- 安装版本上报与日活分别保存成功状态，日活失败不会重复上报安装。

## Android 设备标识

通过已有的 `expo-application.getAndroidId()` 取得 Android ID，使用应用专属前缀和 SHA-256
派生设备标识，不传输原始 Android ID，也不申请电话、IMEI 或广告标识权限。
为兼容已发布服务器，派生值保留已有 UUID v4 格式；它是确定性哈希标识，并非随机生成的 UUID。
Android ID 暂时不可用时跳过并重试，避免退化为反复新增随机设备。
iOS 继续使用原有安全存储中的安装标识，不承诺卸载重装稳定。

Android 8 及以上，同一设备、系统用户和应用签名下，普通卸载重装的 Android ID 保持一致。
恢复出厂、更换系统用户或应用签名可能改变该值；Android 8 系统升级前已安装的应用存在官方说明的例外。
发布时应持续使用同一签名密钥。

旧版使用随机安装标识，首次升级会切换为稳定标识；旧标识与设备没有可恢复的映射，
因此不会猜测或删除历史设备记录。这次转换可能新增一条设备记录，后续普通重装不再新增。

参考：[Android ID 官方说明](https://developer.android.com/reference/android/provider/Settings.Secure#ANDROID_ID)、
[Android 8 标识变化](https://developer.android.com/about/versions/oreo/android-8.0-changes#privacy-all)。

无需数据库迁移。日活查询使用现有活跃事件及其事件类型、时间索引，按平台和日期聚合。
上线后台代码和 admin 构建产物后可查看历史；安卓日活从安装新版并实际打开应用后开始积累。
