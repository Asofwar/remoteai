# 手机端多图追加与待发送排序实机回归

## 问题与修复

在 Android 实体机上复现：任务运行时，先追加两条各含 3 张图片的消息，
再给第三条消息添加图片并展开键盘，发送按钮被挤到聊天区域下方，无法点击。
收起键盘后按钮恢复，三条消息共 9 张图片均能送达真实模型。
这组用例的直接原因是布局溢出；没有复现图片上传或批量提交失败。

现在待发送区与输入区共用有高度上限的容器，队列列表和草稿内容可以收缩、滚动。
添加、聊天设置和发送按钮位于草稿滚动区域之外；收起键盘后输入区仍贴近底部。
队列标题栏保留操作空间，长草稿、图片和引用不会继续向下挤走发送按钮。

## 实机环境：2026-09-15

- USB 连接的 Android 实体机：2109119BC，Android 14，1080 × 2400。
- 同一局域网中的 Hyper-V Windows 11 虚拟机 `win11`，设备名 `ZH2`。
- 虚拟机 PC 应用保持 1.5.12；手机原安装版为 1.5.10，覆盖安装本次源码构建的 arm64 Release 调试包。
- 沿用实际 P2P 连接、真实模型及虚拟机上的 PowerShell 等待任务，未使用模拟聊天服务。
- 图片为本次生成的红、绿、蓝矩形，未发送相册中的个人照片；安装时保留应用数据。

## 已验证场景

| 场景 | 实际结果 |
| --- | --- |
| 单条消息包含 3 张图 | 成功发送，模型识别红、绿、蓝 |
| 原安装版连续追加三条三图消息 | 第三条展开键盘后发送按钮不可见；收起键盘后可发，9 张图全部送达 |
| 修复版连续追加三条三图消息 | 键盘始终展开，三次发送按钮均可见、可点击，消息成功入队 |
| 上移、下移及首尾边界 | 首项不能上移、末项不能下移；A/B/C 调整成 B/C/A |
| 排序后自动发送 | 模型按 B、C、A 顺序逐条描述 9 张图，队列清空 |
| 多图、长文本、纯图片、普通文本混合追加 | 4 条消息分别入队，长草稿仍能滚动并发送 |
| 滚动队列后删除 | 只删除指定的临时消息，其余 3 条保留 |
| 编辑已排队的多图消息 | 3 张图片全部恢复到草稿，改写文字后成功重新入队 |
| 运行中立即发送纯图片消息 | 模型在等待任务结束前确认收到蓝色矩形；其余 2 条仍在队列 |
| 最终版混合队列再次排序 | 调整为 MIX-A-EDITED、MIX-B；模型按此顺序收到图片和文字，队列清空 |
| 键盘开关与运行中响应 | 输入和队列操作正常，收起键盘后无多余底部留白；PC 主进程响应正常 |
