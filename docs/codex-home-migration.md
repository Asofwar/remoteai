# Codex Home 会话迁移验证

会话管理工具栏在“移动到回收站”右侧提供“迁移到 Codex Home”。选择会话后，可将其移至其他已配置的 Home，保留对话记录和项目路径。目标已有相同会话 ID 时跳过，不覆盖目标会话。

迁移前应结束所选会话中的任务，并使用目标 Home 启动一次 Codex，初始化会话数据库。

## 日志冲突修复

两个 Home 的 SQLite 日志 ID 分别自增，相同数字不代表同一条日志。直接恢复原 ID 会触发 `INSERT OR REPLACE`，覆盖目标其他会话的日志。

跨 Home 恢复时，仅在内存中的迁移副本清空日志 ID，由目标数据库分配新 ID。原始备份仍保留源 ID，失败时可以完整还原源会话。

实测步骤及结果：

1. 在两个 Home 中实际创建对话，记录不同标记。
2. 在会话管理中选择源测试会话，通过新按钮选择目标并迁移。
3. 源列表移除该会话；目标同一项目分组同时显示迁入会话和原有会话。
4. 在续聊之前比较 SHA-256：迁入文件与源原文件一致，目标两份已有文件均未改变，项目路径不变。
5. 指定目标 `CODEX_HOME`，按各自 UUID 分别续聊，确认两份上下文独立保留。
6. 请求期间打开代理会话页面，观察活跃状态与自动刷新，并操作刷新按钮，界面正常响应。

测试配置注意：复制源配置时，必须同时调整其中显式设置的 `sqlite_home`。最初沿用了源数据库路径，目标没有独立数据库，迁移按预期失败并还原源文件；修正测试配置并初始化独立目标数据库后，上述迁移及续聊通过。
