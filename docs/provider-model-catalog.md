# 自定义模型目录

## 官方模型列表

官方账户的模型查询优先请求官方接口，成功后直接使用返回的列表，不再请求 Admin。
官方请求失败、返回错误状态或空／无效列表时，再读取当前云端地址的 Admin `/official-models`。
该顺序适用于代理查询、Codex GUI 模型发现、启动刷新、切换账户和手动刷新。
两处均失败时沿用现有的本地缓存与重试流程。

官方模型发现使用独立的 60 秒网络截止时间，覆盖连接、响应头和完整响应体；
凭据刷新每次最多等待 3 秒，且不能超出剩余预算。模型查询不使用聊天请求的长等待和传输重试，
失败后立即转向 Admin，Admin 使用独立的 60 秒超时。聊天请求的超时和重试行为不变。
模型列表 RPC 最多等待 130 秒，GUI 等待 140 秒，手机和 Web 的模型读取与选择请求等待 150 秒，
为官方查询、Admin 回退及结果同步留出完整时间。

聊天目录首次加载或切换来源失败后，3 秒后自动重试，连续失败按 6、12、24、30 秒退避，
后续最长间隔保持 30 秒。手动刷新、远程端读取与自动重试共用正在进行的刷新；退出会话时取消定时器。
手机和 Web 的模型重试会触发电脑端重新获取，不需要重连。已有可用目录在普通后台刷新失败时继续可用。
自定义中转以已保存的模型配置为准；CLI 能力刷新失败或超过 3 秒时仍可使用这些配置，
并在后台继续补刷。未完成的中转能力查询不会重复发起，旧来源的迟到结果不会覆盖当前模型。

### 请求参数核对（2026-10-12）

对照 [Codex CLI 模型接口](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/endpoint/models.rs)，
接口仍为 `GET /backend-api/codex/models?client_version=<major.minor.patch>`，没有新增必填查询参数。
CLI 自带的版本号去除预发布后缀，额外 Provider 查询参数会保留；官方登录使用 Bearer 凭据和账户 ID。
Remote AI 主动刷新仍查找最新稳定版，失败时使用已知版本；代理保留客户端传入的版本与查询参数。

[CLI 默认客户端](https://github.com/openai/codex/blob/main/codex-rs/login/src/auth/default_client.rs)
的 `User-Agent` 使用版本号。桌面端主动获取模型时现按 `client_version` 生成该请求头，
不再固定为 `codex_cli_rs/0.1.0`；转发已有 CLI 请求时保留其身份，避免发送重复的 `User-Agent`。
admin-go 已使用同一版本生成查询参数与请求头，并通过出站代理测试验证认证和参数。

### Admin 自动更新

管理页面的“自动更新”支持开关和自定义间隔，默认开启、每 30 分钟，范围为 1 分钟至 7 天。
保存设置或模型列表后，开启状态下按所设间隔重新计时；关闭后保留列表，也不会在服务重启时自动刷新。
手动“从官方刷新”和编辑始终可用。修改自动更新设置会阻止此前正在运行的自动刷新结果写回。
配置由所有 Go 实例共享，服务每分钟检查是否到期，失败或空响应仍保留此前的有效列表。

## Codex 配置中的模型选项

“默认模型”的选项直接读取当前云端地址的 Admin `/official-models` 接口，无需先添加官方账户。
打开配置页或点击“重新读取”时更新，保留接口返回的顺序并排除隐藏模型，不再维护本地固定推荐列表。
读取失败时保留本页已加载的选项；首次读取失败时仍可手动输入模型名称。
更新选项不会修改已保存的默认模型，也不会覆盖正在输入的内容。

## 自定义属性

Remote AI 更新 `~/.codex/codex-switch-model-catalog.json` 时，会按 `slug` 匹配模型，
保留手动设置的 `apply_patch_tool_type`、`shell_type`、`base_instructions`、
其他工具能力字段以及未知字段。目录顶层的额外字段也会保留。

模型列表、名称、说明、排序、可见性、API 可用性、推理档位、上下文长度、输入类型和快速模式
仍由供应商配置决定。新模型使用默认属性，已移出供应商配置的模型不会继续出现在当前目录中。

切换供应商或供应商组前，现有模型的非托管属性会自动保存在同目录下的
`codex-switch-model-customizations.json`。再次出现相同 `slug` 时，这些属性会恢复。
直接修改当前模型目录即可；当前条目的内容优先于之前保存的属性。
删除自定义字段会清除它的保存值；程序必需的默认字段会在下次更新时补齐。

匹配使用完整 `slug`，区分大小写。供应商组的模型名包含供应商名称，重命名供应商后会视为新模型。
不同 Codex Home 的自定义属性分别保存。目录或保存文件无法读取、JSON 无效时，更新会报错，
不会用默认目录覆盖原文件。

## 默认上下文容量

普通代理模式使用官方账户时，模型单独设置的容量优先于全局值；只有未单独设置的模型才使用全局值。
例如全局为 272K、某个模型为 1000K 时，该模型使用 1000K，不会被全局值截低。

Codex GUI 的“设置 → 上下文”可分别配置各模型的默认容量，也可添加自定义模型或恢复默认。
这些设置与普通代理模式独立。当前对话的单独设置优先，其次是 GUI 的模型设置；
未配置时，官方模型使用 Admin 官方模型列表中的容量，其他模型使用供应商配置。
Admin 默认值与 GUI 自定义值分别保存，刷新列表不会覆盖用户的自定义值。
后台暂时不可用时保留已读取的默认值；首次发现模型仍使用现有的官方列表回退流程。

修改会在下次发送消息或打开对话时应用，不会中断正在运行的任务。
输入单位为 K Token（1 K = 1000 Token）；实际可用容量仍会扣除模型的预留空间。
Admin 官方模型列表原有的自动刷新行为保持不变，这些设置不构成上游服务的强制容量限制。
