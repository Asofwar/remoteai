# Локальная среда выполнения Coze на Rust

> Основная документация — на китайском языке: [README.md](README.md). Английская версия — [README_EN.md](README_EN.md).
> Этот перевод сделан с китайской версии (коммит `d812abbe`) и может от неё отставать.

Remote AI устанавливает этот необязательный компонент через пункт `coze` в разделе «Плагины» на левой боковой панели. При первом открытии проверяется только его состояние; отдельный подписанный пакет скачивается лишь после того, как пользователь нажмёт кнопку скачивания. Основной установщик не содержит среду выполнения, редактор и модель эмбеддингов.

Go-бэкенд исходного проекта Coze не входит в пакет и не запускается; Docker, MySQL, Redis, Elasticsearch, Milvus, Python и Node.js не нужны.

## Текущая реализация и ограничения

| Задача в исходном проекте | Реализация на Rust | Текущие возможности |
| --- | --- | --- |
| Управление моделями | `src/proxy.rs` | Автоматически использует локальный прокси Codex GUI, каталог моделей и текущий аккаунт Remote AI; ключи исходного проекта не копируются |
| База знаний | `src/knowledge/`, `src/embedding.rs` | Документы, веб-страницы, изображения и отсканированные PDF; обновление источников, исходные изображения, редактирование фрагментов, гибридный поиск, ссылки на источники; прогресс фоновых задач и их отмена |
| Рабочий процесс | `src/workflow/` | Визуальное построение, участие человека и возобновление в Chatflow, переменные, агрегация и распознавание намерений, управление циклами, узлы чатов, чтение и запись баз знаний, SQL, трассировка запусков; совместимость с холстом исходного проекта |
| Узел кода | `src/code_runtime/` | JavaScript, TypeScript и подмножество Python; компиляция или интерпретация на Rust без вызова системных Python и Node |
| Агенты и чаты | `src/agents/`, `src/proxy/` | Ответы на вопросы по базе знаний, самостоятельный вызов инструментов, разрешение на запись в таблицы для каждого инструмента, история вызовов инструментов, память на несколько ходов, настоящий потоковый вывод и остановка |
| Приложения и публикация | `src/projects.rs`, `src/publications.rs` | Сборка приложения из ресурсов, запуск точек входа, рекурсивная фиксация зависимостей при публикации, переключение между версиями; документы баз знаний и записи таблиц продолжают обновляться |
| Совместный доступ | `src/collaboration_access/` | Права на просмотр, использование и изменение в пределах приложения, срок действия и отзыв доступа, изоляция черновиков и истории запусков; ссылки для доступа на этом компьютере |
| Шаблоны и резервное копирование | `src/catalog.rs`, `src/backup.rs` | Локальная галерея шаблонов, экспорт и импорт вместе с зависимостями, полное резервное копирование и восстановление базы данных, включая исходные файлы документов, индексы и историю |
| Инструменты и MCP | `src/plugins.rs`, `src/mcp.rs` | Вызов приложений, рабочих процессов, агентов, баз знаний, инструментов, промптов и таблиц на этом компьютере и возобновление Chatflow; автоматическая регистрация в обоих Codex Home |
| Таблицы | `src/tables/` | Типы полей, постраничный вывод, пакетный импорт в одной транзакции, создание, чтение, изменение и удаление записей, изолированный SQL, создание запросов по описанию на естественном языке с предпросмотром |

Это перенос функций для работы на компьютере, а не замена HTTP/Thrift-API или базы данных Go-бэкенда исходного проекта. Импорт холста отклоняет узлы, для которых ещё нет реализации, и никогда не пропускает их молча. Подробное соответствие узлов описано в [заметках о переносе рабочих процессов](../../docs/coze-workflow-parity.md), а объём поддержки баз знаний и SQL — в [заметках о переносе баз знаний](../../docs/coze-knowledge-parity.md) (обе на китайском языке).

Python использует ограниченный синтаксис Python и стандартную библиотеку Monty и поддерживает точку входа исходного проекта `async def main(args)`; произвольные сторонние пакеты pip и доступ к файлам или сети хоста не поддерживаются. Каждый запуск выполняется в отдельном дочернем процессе Rust с ограничениями по памяти и времени. TypeScript транспилируется на этом компьютере и затем выполняется в ограниченном QuickJS. Поддержку языков нельзя описывать как полноценную среду CPython или Node.

Галерея шаблонов — это локальная библиотека шаблонов, которыми можно делиться; она не подключена к онлайн-магазину, оплате и модерации Coze. Ссылки для совместного редактирования предназначены для приложений, опубликованных на этом компьютере. Чтобы вызывать инструменты с других компьютеров, нужно отдельно включить внешний доступ; он не заменяет вход в облачную организацию и управление командой. Распознавание отсканированных файлов и изображений использует выбранную модель с поддержкой изображений и существующую маршрутизацию через прокси, поэтому его нельзя описывать как гарантированно работающее офлайн.

Публикация фиксирует определения ресурсов по всей цепочке зависимостей, поэтому они не меняются, когда вложенный рабочий процесс публикуется заново. Документы баз знаний, поля и записи таблиц при этом продолжают обновляться. Экспорт отдельного элемента и экспорт шаблона включают связанные настройки и ограничения полей. Функция «Резервные копии» экспортирует всю базу данных; для восстановления нужна та же структура базы данных, а старые ссылки для доступа после восстановления перестают работать.

## Работа и данные

- Команды Tauri только передают работу блокирующим рабочим потокам. Скачивание, распаковка, запуск процессов, доступ к настройкам и проверка состояния не занимают поток окна.
- Редактор слушает случайный порт на `127.0.0.1` и требует учётные данные, которые создаются при каждом запуске. Можно отдельно включить порт только для инструментов; редактор, резервное копирование и операции управления через него недоступны.
- Параметры запуска передаются через stdin; среда выполнения завершается, когда закрывается канал родительского процесса. В Windows фоновый запуск не открывает окно консоли.
- Приложение для компьютера подключается через Responses API Codex GUI, который передаёт текст, изображения и вызовы инструментов; версия клиента подставляется в каталог моделей автоматически.
  При автономных тестах с обычным прокси `/v1` сохраняется совместимость с Chat Completions. Прерванный или завершившийся ошибкой поток не засчитывается как успешный ответ.
- Данные хранятся в `coze/data/coze.sqlite3` в каталоге данных приложения. WAL, внешние ключи и транзакции гарантируют, что сбой индексации не оставит документ записанным наполовину, а удаление документа удаляет и его векторные и полнотекстовые записи.
- Компонент находится в `coze/packages/<version>`; замена пакета не удаляет `coze/data`. Незавершённая загрузка не создаёт отметку о завершённой установке.
- Модель эмбеддингов — закреплённая версия `multilingual-e5-small`, которую Candle выполняет на CPU. Она загружается в память только при первом использовании базы знаний и повторно не скачивается.
- Инструмент MCP `coze_list` возвращает опубликованное содержимое и структуру его входных данных, `coze_call` вызывает это содержимое, а `coze_resume` отвечает на приостановленный Chatflow. Черновики и отключённое содержимое вызвать нельзя. Имена инструментов не меняются, поэтому после публикации нового содержимого не нужно перезапускать чат.
- У JavaScript нет доступа к возможностям хоста, таким как файлы, сеть и загрузка модулей; действуют ограничения по памяти, стеку, времени и объёму вывода. Внешний доступ выполняется через отдельный узел HTTPS и не передаёт учётные данные локального прокси.

## Разработка и проверка

### Вызов из Codex GUI

1. Откройте Coze на левой боковой панели, создайте и опубликуйте нужные рабочие процессы, агентов, базы знаний или инструменты.
2. Вернитесь в Codex GUI, введите в поле ввода `#` или `#название` и выберите опубликованное содержимое в появившемся списке.
3. Опишите задачу и входные данные и отправьте сообщение. Например, выберите `#Проверка остатков` и введите «Узнай остаток товара A на складе».

Выбранный элемент сохраняется как ссылка в сообщениях, очереди и редактируемых черновиках. Модель через уже зарегистрированный MCP-сервер `remoteai_coze` узнаёт требования к входным данным и вызывает нужный ресурс; если имена совпадают, решает ID выбранного элемента. Ввод `#` только запускает уже установленный компонент и не начинает автоматическую загрузку; при первой установке компонент по-прежнему нужно скачать через пункт Coze.

### Доступ для других приложений и компьютеров

Откройте у ресурса «Настройки → Внешний доступ», выберите «Только приложения на этом компьютере» или «Разрешить другим компьютерам», включите сервис и создайте отдельный ключ доступа. Каждый ключ даёт доступ только к одному опубликованному ресурсу, действует от 1 до 365 дней и может быть отключён в любой момент. Ключ показывается только один раз; в настройках есть MCP-конфигурация и примеры API, которые можно скопировать.

- **MCP**: используйте адрес Streamable HTTP `http://<адрес компьютера>:15461/mcp` и заголовок запроса `Authorization: Bearer <ключ доступа>`. Поддерживаются `coze_list`, `coze_call` и `coze_resume`. При согласовании протокола поддерживаются версии 2025-03-26, 2025-06-18 и 2025-11-25; устаревшая отдельная точка подключения SSE не предоставляется.
- **API**: отправьте POST-запрос с JSON на `http://<адрес компьютера>:15461/api/run` с тем же заголовком авторизации. Рабочим процессам и инструментам передавайте `{ "input": { ... } }`, агентам — `{ "message": "..." }`, базам знаний — `{ "query": "..." }`; ресурс определяется по ключу автоматически. Чтобы продолжить чат, передайте полученный `conversationId` в поле `conversation_id`.
- **Возобновление Chatflow**: отправьте `{ "run_id": "...", "interaction_id": "...", "input": { ... } }` на `/api/resume`. Возобновить можно только запуски, созданные с тем же ключом.
- На этом компьютере используйте `127.0.0.1`. Другие компьютеры подключаются по адресу в локальной сети или VPN, по которому доступен этот компьютер; при необходимости откройте выбранный порт в брандмауэре. Доступ через интернет — только через VPN или HTTPS-шлюз; публичный туннель автоматически не создаётся. Этот интерфейс рассчитан на серверы и настольные клиенты; прямые кросс-доменные запросы из браузера запрещены.
- Область доступа и порт — общие настройки этого компьютера; их отключение приостанавливает весь внешний доступ. Remote AI и Coze должны оставаться запущенными; при следующем запуске Coze восстановит настройки прослушивания. Если порт занят, снова включите внешний доступ в настройках. Сетевые настройки не входят в резервную копию содержимого, поэтому восстановление содержимого не открывает сетевой порт.
- Учётные данные запуска редактора отделены от ключей внешнего доступа; внешний ключ не даёт доступа к API управления, черновикам и истории запусков других ключей. После снятия содержимого с публикации прежние ключи больше не могут его запускать; документы баз знаний и записи таблиц продолжают обновляться по существующим правилам публикации.

### Команды проверки

Выполните в корне репозитория:

```powershell
cargo test --manifest-path apps/coze/Cargo.toml
cargo clippy --manifest-path apps/coze/Cargo.toml --all-targets -- -D warnings
node node_modules/typescript/bin/tsc -p apps/coze/ui/tsconfig.json
node node_modules/vite/bin/vite.js build --config apps/coze/ui/vite.config.ts
npm run test -w @codex-switch/coze
npx playwright install chromium
npm run test:e2e -w @codex-switch/coze
node scripts/prepare-coze-model.mjs
cargo test --manifest-path apps/coze/Cargo.toml --test local_embedding -- --ignored
$env:RUSTFLAGS = "-C target-feature=+crt-static"
cargo build --bins --manifest-path apps/coze/Cargo.toml
node scripts/package-coze.mjs apps/coze/target/debug/remoteai-coze.exe .codex-tmp/coze-package
node scripts/verify-windows-runtime.mjs .codex-tmp/coze-package/remoteai-coze.exe
node scripts/verify-windows-runtime.mjs .codex-tmp/coze-package/remoteai-coze-python.exe
node scripts/smoke-coze.mjs .codex-tmp/coze-package/remoteai-coze.exe
```

Нужен Rust 1.96 или новее. `package-coze.mjs` требует новый выходной каталог и проверяет и основную программу, и программу для узлов Python. В macOS и Linux уберите `.exe`. Дымовой тест использует временные данные и тестовый прокси модели и не изменяет базы знаний пользователя и реальные настройки моделей; локальный расчёт эмбеддингов использует настоящие веса.

Сборка для Windows использует статическую библиотеку среды выполнения C, а импорт DLL обеих программ проверяется, чтобы пользователям не приходилось отдельно устанавливать среду выполнения Visual C++.
На других платформах не задавайте указанный выше `RUSTFLAGS` и не запускайте проверку DLL для Windows.

`scripts/smoke-coze-live.mjs` может подключиться к настоящему прокси модели, запущенному приложением для компьютера. Он проверяет потоковый вывод, отмену, ответы со ссылками на источники, вызовы инструментов и их историю, SQL, узлы кода, изображения и отсканированные PDF.
Скрипт также проверяет полное восстановление базы, поэтому ему нужна пустая отдельная рабочая область для приёмочных тестов. Передайте `runtime.json`, ID модели, путь к отчёту, тестовое изображение и отсканированный PDF;
оба файла с изображениями должны содержать текст `Verification code: VX-84620`. В отчёт записываются только результаты тестов, учётные данные запуска в него не попадают.

## Отдельный выпуск

`.github/workflows/coze-runtime.yml` собирает отдельные ZIP-архивы для Windows x64/ARM64, macOS x64/ARM64 и Linux x64. В каждый входят обе программы на Rust, редактор на React, модель для баз знаний и тексты лицензий. Тег выпуска берётся из `runtime.json`, сейчас это `coze-v0.2.1`. Выпуск не помечается как последний (latest) выпуск Remote AI, и правило тегов `v*` основного приложения не запускает его повторно.

Основной сценарий выпуска вызывает этот сценарий CI; его также можно запустить вручную отдельно. Пакет подписывается существующим ключом `TAURI_SIGNING_PRIVATE_KEY`, а приложение для компьютера проверяет подпись встроенным открытым ключом перед распаковкой. Опубликованные версии нельзя перезаписать: при любом изменении уже опубликованного пакета нужно одновременно обновить версию Cargo и `runtime.json`. Загрузчик закреплён за совместимой версией, поэтому изменение протокола среды выполнения требует соответствующей доработки приложения для компьютера.

Успешная локальная сборка не означает, что прошли сборки для всех пяти платформ и подписанный выпуск на GitHub. Для загрузки в рабочей среде соответствующие задачи CI должны успешно опубликовать выпуск; не считайте ещё не существующий выпуск уже доступным.
